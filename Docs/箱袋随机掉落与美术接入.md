# 箱袋随机掉落与美术接入

> 2026-11-02最新镇守分布修订（优先于下文旧双怪／19只描述）：受镇守箱／袋须通过原有地面布局保证玩家先击败挡路怪物，才能到达任一交互位；不再要求每个容器固定数量的怪物，也不固定每层普通怪总数。箱／袋开启、拾取不检查任何守卫关系或存活状态。用户明确允许破墙另开入口绕过战斗。新局保留8个受镇守、2个无镇守容器及1只通道怪、2只自由怪的试配比例；物品守卫覆盖受镇守容器的全部原有地面交互入口，按入口数生成，新容器不写入守卫关联ID。地形不变时，以容器为永久障碍、仅物品守卫为敌方障碍从出生点搜索，所有受镇守容器都必须没有可达交互位；击败挡路怪后依靠普通移动和交互自然可取。旧存档保留既有地图、怪物和兼容字段，不补怪、不重排。

## 新局试配

第1～4层每层为10个容器：2个装备箱、5个财宝箱、3个消耗品袋。2026-11-02用户修订：同类箱／袋不要距离过近，每个受镇守容器至少有两只怪保护，开启后仍占格，生成时避免容器堵路。新局保留8堆角落镇守、2堆无镇守；本轮每个受镇守容器分别绑定两只四向相邻守卫，共16只物品守卫，另有1只通道守卫及2只自由怪，每层合计19只普通敌人。2026-11-02后续修订：取消守卫锁定，守卫存活时也可开启和拾取箱／袋；双怪只保留为空间分布与路线风险，战斗仍逐只进入单敌战斗。出生格距所有怪物至少3格曼哈顿距离。

同类容器的最小曼哈顿距离试配为3格，入口为 `MapGenerator.MinimumSameContainerDistance`；该数值可调，不作为用户已冻结的数值。生成时将全部容器视为永久障碍，从出生点检查剩余地面的连通性、全部容器的相邻交互位与前进／返回门的相邻交互位；不依赖开箱、拾空或破墙打通道路。不满足时重新生成，不能降低间距、守卫或通路约束。

| 容器 | 随机结果 | 数量与权重 |
|---|---|---|
| 第1层装备箱 | 铁剑／迅捷剑／铭文剑 | 等权，每箱1件 |
| 第2～4层装备箱 | 铁剑／迅捷剑／铭文剑／精制长剑／木盾／皮甲／启迪皮甲／铁甲 | 权重9／9／9／3／6／6／6／2，每箱1件；武器合计60%、非武器40% |
| 财宝箱 | 碎矿石／晶簇／古代遗物 | 权重60／30／10；分别随机2～4件／1～2件／1件 |
| 消耗品袋 | 治疗药剂／力量精华／敏捷精华／智慧精华／强攻药剂 | 权重6／1／1／1／1，每袋1件 |

每次开启只抽一种物品，再抽该物品的件数。武器继续按本局角色绑定与允许类型过滤；无候选时只允许本角色可用铁剑保底，保底也不存在则报配置错误。

内容在首次有效开启时确定，开启前只显示容器名称。守卫存活不再阻止开启或拾取；首次有效开启推进一次容器随机序列，重复交互不重抽。高上限容器仍优先进入镇守组。

2026-11-02后续用户明确：新局怪物等级等于所在层数，第1～4层的物品守卫、通道怪、自由怪统一为Lv.1～4，第5层首领为Lv.5。取消按容器最高稀有度＋1分配守卫等级的旧试配规则；容器品质不再影响等级。每升1级生命＋4、攻击意图伤害＋1，格挡与行动循环保持原规则。只在生成新局时赋值，继续旧存档不按楼层重算已有等级。

背包已满也会开启并确定内容，物品原地保留；空间不足时继续沿用能拿多少拿多少。未取空时仍阻挡、可再次拾取，使用已开启贴图且保持不透明；新局容器全部取空后保留不透明的开启外观及实体碰撞，取消名称和交互；该格仍不可通行。丢弃物仍是小型可踩过的散落物，装备散落物使用装备图标。

第5层首领的固定古代遗物奖励保留，不改成随机装备奖励。旧存档已有容器内容不重抽，不强制套用新的2／5／3比例；旧容器取空后的状态也保留。

## 随机与存档

`RunData.containerVersion = 1` 标记新供应规则，版本0继续处理已有内容。2026-11-02新布局容器增加 `permanentObstacle` 和 `secondGuardEnemyId`，原 `guardEnemyId` 保留作为第一只守卫；缺失新增字段的旧存档不补怪、不移动容器，保留单守卫布局与取空可通行／25%透明残影行为；本次取消开启／拾取锁定同样适用于旧存档，不修改其物品内容。新局保存 `containerRules` 试配快照、独立 `containerRandom` 随机进度，以及每个容器的类型、未开／已开状态和开启后的实际物品实例。后续试配不改写正在继续的旧局。

开启不消耗地图、战斗洗牌或升级选牌随机流；相同种子、规则与开箱顺序得到相同内容，副属性选择不影响结果。重复交互、部分拾取及存读档均不重抽；尚未开启的容器继续按已保存的随机进度抽取。

试配入口为 `Assets/MagicCavePrototype/Runtime/ContainerLoot.cs` 中 `ContainerLootRules.Defaults()`。每层容器数量必须合计10个，权重为正，数量范围为1～20；新局复制配置进存档。

## 素材对应与导入

| 原始素材 | 使用方式 |
|---|---|
| `Proactive Object/Chest/Chest_EquipmentChest.aseprite` | 未开启装备箱 |
| `Proactive Object/Chest/Chest_TreasureChest.aseprite` | 未开启财宝箱 |
| `Proactive Object/Chest/Chest_ConsumablesBag.aseprite` | 未开启消耗品袋 |
| `Proactive Object/Chest/Chest_All_Empty.aseprite` | 48×16横排三格，左至右为开启装备箱、开启财宝箱、空袋；逐格切为16×16 |
| `Equipmen/Equipment.aseprite` | 256×256图集；当前三槽原型只接入盾、胸甲、剑，共8个现有装备图标 |

装备图集以左上为原点，使用16×16完整画布。盾、胸甲、剑所在行的左上Y分别为16、48、144；棕／灰／白／黄列的左上X分别为16、48、80、112。木盾用棕盾，皮甲用棕胸甲，启迪皮甲用白胸甲，铁甲用灰胸甲，铁剑用灰剑，迅捷剑与铭文剑共用白剑，精制长剑用黄剑。图中颜色只用于本轮美术对应，不据此新增稀有度或装备规则。

工具 `Tools/export_validation_sprites.py --container-art-destination <项目外暂存目录>` 导出三张开启图及八张装备图。导出不会改原始Aseprite；写入Assets、导入、16 PPU、Single Sprite、Point、无压缩、无mipmap及素材资产绑定均通过Unity MCP执行。`PrototypeSceneBuilder.EnsureArtAssets()` 保留这些引用，后续重建不会丢失。

背包及地面丢弃装备使用新装备图标。素材中其他部位不自动扩展当前三槽玩法。
