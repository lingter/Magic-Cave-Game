# 角色属性与装备系统设计案

> 当前实现的副属性加成为每点1%。本文保留的10%数值属于早期迭代记录，现行规则见完整设计与试玩说明。

> 本文件保留迭代讨论记录。完整整合版及首轮默认配置见[《角色属性与装备系统完整原型设计_v1.0》](角色属性与装备系统完整原型设计_v1.0.md)，后续实现以整合版为准。

版本：v0.3；日期：2026-10-25；状态：设计修订，尚未实施。

本案响应新增需求：角色模板具有固定初始属性；局内升级、装备和增益改变属性；战斗读取属性计算伤害；模板限定可穿戴的装备类型。

用户已明确的补充规则：武器模板定义基础ATK及属性修正系数；实际ATK由基础ATK加上角色属性乘修正系数得到；攻击卡按实际ATK的倍率造成伤害；卡面直接显示计算后的伤害。每个武器模板只绑定一个角色模板，探索只生成与本局角色模板匹配的武器。其余成长、装备数值、防御与持续时间等仍是建议，不代表协作者已确认。

用户进一步明确：力量、敏捷、智慧三项属性均纳入原型；职业决定主属性，例如战士以力量为主属性。每局开始时，玩家从另外两项中选择一项副属性，副属性提供“该属性数值×10%”的最终伤害加成。下文将“最终伤害”解释为玩家输出端在目标减伤前的最后一个乘区；作用范围和生命周期细节按本案建议落实。

## 2. 核心结构：模板不变，本局成长，战斗临时叠加

角色模板定义固定初始属性、成长表、所属公会、基础武器配置、初始卡组和装备许可。开始新局时创建独立角色实例，探索中的修改不能写回模板。

属性分成四个来源层：

1. 模板初始值。
2. 本局固定成长：出发时的天赋快照、升级成长、本局永久增益。
3. 当前装备提供的属性。
4. 有效临时增益：若干场战斗增益、当前战斗增益、当前回合增益。

“永久增益”默认指本次探索内永久，正式结束本局后清除。局外永久成长仍由公会天赋管理。回城存档不清除本局成长，也不重新套用城镇最新天赋。

首版各来源采用加法：

```text
有效属性 = 模板初始值 + 天赋快照 + 等级成长 + 本局永久增益
         + 当前装备加成 + 当前有效临时增益
```

先按来源汇总，再对结果做合法范围限制。生命上限至少为1，力量、敏捷、智慧与物理防御至少为0。上述基础属性的来源先相加；武器的百分比属性修正是将有效属性转换为ATK的系数，不是额外提高角色力量的百分比增益。

## 3. 首版属性及模板

力量、敏捷、智慧是角色属性。武器模板决定哪些属性参与ATK计算及各自修正系数，同样的力量对不同武器可以有不同收益。力量不再直接加到每张攻击卡的最终伤害上。

| 属性／状态 | 用途 | 首版骑士初始值 |
|---|---|---:|
| 最大生命 | 当前生命的上限 | 60 |
| 当前生命 | 受伤与治疗后跨战斗保留 | 新局按最大生命填满 |
| 力量 | 武器力量修正；可按职业成为主属性或被选择为副属性 | 10，暂定；战士／骑士的主属性 |
| 敏捷 | 武器敏捷修正；副属性候选；另按现有建议增加防御牌格挡 | 5，暂定 |
| 智慧 | 武器智慧修正；副属性候选；首版即可选择并提高最终伤害 | 5，暂定 |
| 实际ATK | 当前武器基础ATK与角色属性修正的派生结果 | 按武器模板计算 |
| 物理防御 | 每段物理伤害的固定减免 | 0 |
| 等级／经验 | 驱动本局成长 | 1／0 |

当前生命、当前格挡、当前能量属于运行状态，不参与属性来源求和。格挡是会被消耗的防护量，物理防御是每段生效的减免，两者分别显示。

首版仍只开放战士公会的骑士模板，但力量、敏捷、智慧全部提供数值、界面、物品、战斗计算与存档支持。智慧即使没有专属法术卡，也能通过副属性加成提高现有攻击牌的伤害；武器模板同样可以配置智慧修正。普通物品池应包含智慧来源，不再排除智慧装备。是否成为副属性不会改变武器原有修正系数。

协作者列出的速度、闪避、暴击、理智及元素抗性作为后续扩展方向。现阶段不改变玩家先手、每回合3能量、抽5张牌的规则。大天赋的开场能量、开场格挡、战后恢复继续作为机制效果，不能混入力量或敏捷。

### 每局主、副属性选择

职业／角色模板配置唯一主属性 `primaryAttribute`，取值为力量、敏捷或智慧；玩家不在出发时重选主属性。战士／骑士的主属性为力量；未来其他职业的主属性通过各自模板配置，不根据当前最大数值动态判断。

每次开始新局时，在真正创建地图和消耗本局随机流之前展示角色确认与副属性选择。战士显示“主属性：力量”，只提供“敏捷”与“智慧”两个候选，玩家明确选定后点击“开始探索”。选择本身不额外赠送属性点；两项均来自角色模板的固定初始属性。面板预览三项数值及两种选择各自提供的最终伤害加成。

```text
副属性最终伤害加成率 = 当前有效副属性值 × 10%
副属性最终伤害倍率 = 1 + 当前有效副属性值 × 0.1
```

例如选择智慧，智慧5提供＋50%最终伤害，即乘1.5；智慧10提供＋100%，即乘2，而不是仅乘1或固定加10点伤害。副属性取当前有效值，包含等级、装备、天赋及有效增益；主属性和未选择的第三属性不会自动获得这项额外乘区。

主属性仍按武器模板修正参与ATK，不额外赠送一个未经定义的主属性伤害倍率。被选择的副属性既可以按武器修正参与ATK，又可以提供最终伤害加成，这是两个明示的不同收益；未选择的第三属性仍可以参与武器修正和其余已配置效果。

副属性类型锁定到本局正式结束，不在探索、战斗或存档回城时切换；数值可以正常成长。继续存档恢复原选择，下一次新局重新选择。本案建议这一生命周期以避免根据每次掉落随时重选副属性。

### 升级成长建议

沿用经验曲线 `20 + 10 × (当前等级 - 1)`，每级仍获得一次三选一，可跳过。

骑士建议成长：每升1级最大生命＋4；到达偶数等级时主属性力量＋1；到达3的倍数等级时本局选择的副属性＋1；未选择的第三属性和物理防御不自动增加。即：

```text
等级L的最大生命成长 = 4 × (L - 1)
等级L的主属性成长 = floor(L / 2)
等级L的已选副属性成长 = floor(L / 3)
```

升级不直接治疗：当前生命保持不变。因此60/60升级后为60/64。连续升级逐级发放成长和选牌机会；跳过选牌不影响属性成长。失败时的5点经验沿用旧规则，只计结果统计，不触发升级或治疗。

选择智慧的骑士到3级时，等级成长提供力量＋1、智慧＋1，敏捷不增加；选择敏捷则提供力量＋1、敏捷＋1。该分配是成长建议，不改变模板初始三属性，也不把已有敏捷值转换为智慧。

力量训练建议映射为力量；体魄训练映射为最大生命；盾术训练映射为敏捷。力量＋1对ATK的实际收益取决于武器修正，不能再把旧天赋“每段伤害＋1”与新版“力量＋1”视为等价。新局采用新版映射并重新调试数值；旧局按第9节保留旧公式。

## 4. 装备槽与模板许可

首版提供主手、副手、护甲三个槽位。装备分成“放在哪个槽位”和“属于哪种类型”，角色模板分别声明允许类型。武器另有精确的角色模板绑定，不能仅凭同属单手剑就判定可用。

| 骑士槽位 | 允许类型 | 不允许示例 |
|---|---|---|
| 主手 | 单手剑 | 弓、法杖、匕首、双手剑 |
| 副手 | 盾牌 | 法器、第二把武器 |
| 护甲 | 轻甲、重甲 | 法袍 |

这张许可表是首版建议，来自骑士当前剑盾定位，并非协作者已给出的装备白名单。后续模板可以复用同一套槽位，配置不同白名单；公会归属不自动等于装备许可。

### 武器模板与角色模板绑定

每个 `WeaponTemplate` 必须填写唯一的 `ownerCharacterTemplateId`。允许一个角色模板拥有多种武器模板；每一种武器模板只能属于一个角色模板。武器模板定义基础ATK与属性修正，例如力量150%、敏捷0%、智慧0%；首版武器实例引用该模板，不自行随机生成或改变修正系数。

```text
骑士模板
  ├─ 铁剑模板：所属角色＝骑士，基础ATK及属性修正独立配置
  └─ 精制长剑模板：所属角色＝骑士，基础ATK及属性修正独立配置

法师模板
  └─ 法杖模板：所属角色＝法师，基础ATK及属性修正独立配置
```

穿戴武器时必须同时满足“武器所属角色模板等于本局角色模板”“装备类型获准”“槽位匹配”。绑定按稳定ID判断，不按角色名称、公会或武器外观判断。副手盾牌与护甲首版沿用类型许可；如果未来副手也属于攻击武器，同样执行武器绑定。

探索中的所有武器生成入口，包含地图容器、敌人奖励及未来事件奖励，均先按本局角色模板过滤武器模板池，再执行稀有度与权重抽取。即使其他角色也能用单手剑，本局也不会生成属于该角色模板的剑。候选池为空时跳过武器奖励或使用本角色基础武器模板作为明确保底，不能回退到全职业池。存档继续时恢复已生成实例，不重新抽取。

首版同角色模板内换装更新基础ATK、属性修正和卡面伤害，不自动替换卡组；卡牌的武器需求由配置校验。基础武器同样引用绑定该角色的武器模板：空主手时使用该基础模板计算ATK，而不是把ATK置0。基础武器是模板能力，不生成可出售或带出的免费物品；空副手仍保留模板基础盾击能力。后续增加双手占用或不同武器卡组时另行扩展。

装备操作只允许在探索界面进行，战斗、升级奖励和带出结算期间锁定。装备须已在背包内；换装前校验模板许可、槽位、物品归属和交换后的背包容量。全部通过才一次性完成交换。失败不移动物品、不修改属性。

装备不堆叠，每件有独立实例ID。已穿装备不占常规背包格，但正式结束时与背包物品共同参与带出选择，不能免费带出。卸装需要一个空格；满包时允许新装备与旧装备交换，旧装备放入新装备释放的格子。直接丢弃已穿装备需先卸下。

建议首批内容：

| 装备 | 类型／槽位 | 武器配置或属性 | 稀有度 |
|---|---|---|---|
| 铁剑 | 单手剑／主手 | 绑定骑士；基础ATK与属性修正由模板配置 | 常见 |
| 精制长剑 | 单手剑／主手 | 绑定骑士；可采用不同基础ATK及修正，具体值待调试 | 罕见 |
| 木盾 | 盾牌／副手 | 敏捷＋1 | 常见 |
| 皮甲 | 轻甲／护甲 | 最大生命＋6 | 常见 |
| 启迪皮甲 | 轻甲／护甲 | 最大生命＋4、智慧＋1，用于首版智慧构筑验证 | 常见 |
| 铁甲 | 重甲／护甲 | 物理防御＋1 | 罕见 |

首版不增加随机词条、耐久、强化、套装或商店。武器不强制要求等级。用于演算的“基础ATK10、力量修正150%”不自动成为所有武器的正式平衡数值。

### 生命上限变化

除新局初始化外，提高上限均不增加当前生命；降低上限只执行 `当前生命 = min(当前生命, 新上限)`。这样反复穿脱皮甲不会回血。首版增益物品不提供临时生命上限，减少到期截断生命造成的困惑。

## 5. 增益物品与持续时间

首版增益物品只在探索中使用，沿用药剂交互；不直接开放战斗中喝药。协作者的“消耗品牌”留给后续独立设计。

| 物品 | 效果 | 叠加与消耗 |
|---|---|---|
| 力量精华 | 本局力量＋1 | 不同次使用累加；每件使用时消耗 |
| 敏捷精华 | 本局敏捷＋1 | 与力量精华采用同一属性增益结构 |
| 智慧精华 | 本局智慧＋1 | 可提高智慧武器修正；选择智慧为副属性时还提高最终伤害倍率 |
| 强攻药剂 | 接下来2场战斗力量＋2 | 同效果不叠数值；再次使用仅刷新为2场 |
| 治疗药剂 | 恢复20生命 | 延续现状；满血不可使用、不消耗 |

强攻药剂剩余次数已为2时禁止重复使用、不消耗物品。与力量精华、装备和天赋的力量加成正常相加。

所有增益配置持续范围与叠加规则，实例记录来源、数值、剩余场次或回合：

- 本局：跨战斗、切图、存档回城保留，正式结束或新局时清除。
- 若干场战斗：探索中可查看“待生效＋剩余场次”；只在真正进入战斗时纳入战斗属性，本场结算完成后扣1。最后一场结束时移除；死亡随整局结束清除。
- 单场战斗：离开该战斗时移除。
- 单回合：在配置的所属方回合结束时移除；当前战意仍在玩家回合结束时清除。

次数不按移动步数、等待时长、切图或返回门存档消耗。同一战斗结算只能扣一次，复用现有防重复结算入口。暂停退出仍按最近手动存档恢复，不因此新增战斗中存档或自动保存。

## 6. 伤害与格挡计算

卡牌需声明效果标签。物理是伤害类型，武器／法术／格挡转换是计算来源，二者不能混为一个字段。

攻击分三步：先用武器模板计算实际ATK，再用卡牌倍率和固定加成得到每段基础伤害，最后乘副属性最终伤害倍率。修正150%表示贡献“属性值×1.5”，不是在基础ATK上再增加150%。未配置的属性修正视为0。

```text
实际ATK = max(0, 武器基础ATK
                 + 有效力量 × 武器力量修正
                 + 有效敏捷 × 武器敏捷修正
                 + 有效智慧 × 武器智慧修正)

副属性最终伤害倍率 = 1 + 当前有效副属性值 × 0.1
武器攻击每段基础伤害 = max(0, 实际ATK × 卡牌本段伤害倍率 + 本段固定伤害加成)
武器攻击每段原始伤害 = 武器攻击每段基础伤害 × 副属性最终伤害倍率
防御牌获得格挡 = max(0, 卡牌基础格挡 + 有效敏捷)
盾击原始伤害 = max(0, 结算该牌时的当前格挡 + 本段固定伤害加成) × 副属性最终伤害倍率

物理结算伤害 = max(0, 原始伤害 - 目标物理防御)
消耗格挡 = min(目标当前格挡, 物理结算伤害)
生命损失 = 物理结算伤害 - 消耗格挡
```

角色属性按武器修正在实际ATK中计一次，攻击卡不得再把力量直接加一次；仅本局选中的副属性另提供一次最终伤害乘区。装备如同时提供基础ATK与力量，应分别进入对应计算来源；首版武器表只配基础ATK和修正，不默认额外赠送力量。原 `attackBonus` 不可直接与新版公式相加。

建议战意暂时保留“本回合每段攻击固定伤害＋2”的位置，放在卡牌倍率之后、副属性最终倍率之前；若以后设计“力量＋2”，则先改变力量、重新计算实际ATK，再乘卡牌倍率，两者收益不同。盾击保留格挡转换公式，不读取武器ATK或力量、不消耗自身格挡；战意与副属性最终倍率仍可增加盾击伤害。

本案建议副属性倍率作用于玩家直接造成的伤害，包括武器攻击、格挡转换的盾击，以及后续接入的法术或神圣直接伤害；不作用于格挡获得量、治疗量、生命上限或敌人伤害。持续伤害、反伤与召唤物尚未接入，不能默认再乘一遍。目标物理防御、抗性和格挡在副属性倍率之后处理，因此“＋100%最终伤害”不会跳过目标防御，也不保证实际生命损失恰好翻倍。

攻击卡由固定点数改为倍率配置。重击按用户示例设为150%实际ATK；打击可先按100%试配，连击每段倍率与迅击倍率另行调试，不再把旧15／6／4／5点作为新版攻击公式的基础值。防御／固守／稳守的基础格挡暂沿用5／12／4。

防御在格挡之前生效，每段分别减免；伤害允许降到0，不强制保底1。连击逐段结算，第一段击杀后停止后续段。敌人的攻击也经过同一物理防御与格挡流程，默认敌人物理防御为0，以保持旧战斗基准。

沿用用户的武器示例：基础ATK10、力量修正150%、有效力量10，其他武器修正为0，则实际ATK为 `10 + 10 × 1.5 = 25`。重击倍率150%，基础伤害为 `25 × 1.5 = 37.5`。

新增副属性示例：战士主属性力量，玩家选择智慧，当前有效智慧10，得到最终伤害加成100%、倍率2。重击原始伤害为 `37.5 × 2 = 75`，卡面直接显示75。若目标物理防御1、格挡5，则造成74点结算伤害、消耗5点格挡，最终损失69生命。有效智慧5时倍率1.5，同一重击为56.25；有效副属性0时为37.5。

建议首版支持小数伤害及生命／格挡状态，显示最多两位小数，末尾0省略，因此可以显示37.5或56.25。计算过程保留精度，乘完副属性最终倍率后，每段原始伤害统一按四舍五入量化到0.01再减防、抵挡与扣血；不在属性修正、ATK或卡牌基础伤害阶段提前截断。百分比建议存为整数基点，数值采用定点计算；卡面和结算使用同一个量化结果。此精度方案属于实施建议，用户已明确的计算顺序不受影响。

### 后续伤害类型预留

协作者列出的物理、火／雷／冰、神圣、黑暗均保留独立类型。首版只接入物理伤害，但智慧属性与智慧武器修正即可生效。未来接入法杖、法术卡时沿用实际ATK、卡牌倍率及副属性最终乘区；元素及黑暗按对应百分比抗性减免并采用统一小数精度，再进入格挡；神圣作为真实伤害直接扣生命，穿透防御及格挡。抗性和神圣结算属于后续提案，不能在当前卡牌上隐式启用。

## 7. 交互和物品闭环

增加“角色”面板：同时显示力量、敏捷、智慧，并标记主属性与本局副属性；显示模板、等级、生命、实际ATK、物理防御、三个装备槽和当前增益。额外列出“副属性：智慧10；最终伤害＋100%”。属性详情能展开模板、等级、天赋、装备、增益各项来源；待下一场生效的药剂单独标记。智慧在首版是可见且生效的属性。

背包装备显示“装备／替换”按钮；不合模板时显示明确原因，例如“该武器绑定其他角色模板”。武器详情同时显示基础ATK、各项属性修正和按当前角色算出的实际ATK；换装预览显示ATK、副属性伤害倍率和各攻击卡的伤害变化，避免玩家只比较基础ATK。智慧装备即使不改变当前武器ATK，也可能通过智慧副属性提高卡面伤害。其他装备预览属性增减，并提示上限下降可能截断当前生命。

### 卡面直接显示伤害

武器攻击牌的正文直接显示包含副属性倍率的本段原始伤害，不要求玩家自行计算百分比。以上智慧10示例，重击正文为“造成75点物理伤害”，次要说明为“150%实际ATK；副属性最终伤害＋100%”；展开详情可查看“实际ATK25＝基础10＋力量10×150%；25×150%×2＝75”。

多段牌显示“每次造成X点伤害，共2次”，不只显示总和；盾击实时显示按当前格挡和副属性倍率计算的伤害。换装、升级、增益生效／失效、战意变化、格挡变化以及有效副属性数值变化后，相关卡面立即更新。探索卡组面板按当前探索属性展示，尚未进入战斗的药剂影响另标“下一战”；战斗手牌按本场有效属性展示。

卡面正文显示攻击本身的伤害；战斗中存在确定目标时，卡面同时直接显示目标减免和格挡后的预计生命损失。例如重击正文“造成75点物理伤害”，目标行“预计生命损失69”；详情显示“物理防御减免1；抵消格挡5”。当前原型只有一个敌人，因此可始终显示这条目标行；未来多目标时随选定目标更新。目标预览同步显示这些结果，敌人意图也显示攻击值与预计生命损失。卡面、目标预览与真实结算共用同一计算逻辑，多段预览按顺序模拟格挡消耗。

掉落建议：保持每张常规地图10堆物品与镇守关系；其中最多2堆改从新增装备／增益池抽取，第一张地图保底至少一件本局角色模板绑定的武器和一件增益物品，其他堆保持旧分布。所有武器候选必须先执行角色模板过滤，稀有度保底同样不能越过绑定限制。新增物品的地图随机流单独派生并保存，不消耗战斗洗牌或选牌随机流；新版本不承诺与旧版本同种子掉落一致。

装备按独立实例保存，消耗品仅在同配置下堆叠、每格上限20。物品保持原首次获取时间与入包顺序，换装、卸装和丢弃再拾取都不刷新。主动带出最多10件、失败带出最多5件；候选集合扩展为背包与已穿装备，同一实例只能出现一次。

仓库当前只保存四类物品数量，需扩展为“旧材料／消耗品数量＋装备实例列表”；装备每件占1仓库容量，仍不开放从仓库携物入局。装备实例的所有权转移与物品、金币、声望使用同一局ID提交，防止中断后重复入库。建议新增装备及增益首版均不可出售／捐赠，后续商店设计再配置价格。

## 8. 数据结构和代码接入建议

| 数据 | 责任 |
|---|---|
| `CharacterTemplate` | 稳定ID、版本、力量／敏捷／智慧初始值、唯一主属性、成长规则、公会、初始卡组、基础武器模板ID、装备许可 |
| `EquipmentDefinition` | 稳定ID、类型、槽位、固定属性、稀有度；承载非武器装备的定义 |
| `WeaponTemplate` | 稳定ID、版本、唯一所属角色模板ID、类型与槽位、基础ATK、力量／敏捷／智慧修正、稀有度 |
| `EquipmentInstance` | 实例ID、定义ID、首次获取记录；首版无随机词条 |
| `AttackCardDefinition` | 稳定ID、伤害来源、伤害类型、各段ATK倍率、段数与武器需求；特殊牌可使用格挡转换来源 |
| `ModifierDefinition / ModifierInstance` | 修改哪个属性、数值、来源、范围、叠加策略、剩余次数 |
| `RunCharacterState` | 模板ID与定义快照、主属性快照、本局副属性类型、天赋快照、等级、当前生命、装备引用、本局增益 |
| `StatCalculator` | 按来源得到三项有效属性，结合武器模板计算实际ATK；由本局副属性计算最终伤害倍率及明细 |
| `CombatResolver` | 统一计算卡牌基础伤害、副属性最终乘区、小数量化、分段减免、格挡与预览 |
| `WeaponLootResolver` | 按本局角色模板过滤武器池，再进行稀有度和权重抽取 |

模板、装备及物品定义建议使用ScriptableObject，运行状态使用可序列化数据。不是每次修改都对最终属性做加减，而是修改来源并重新计算，避免卸装、到期、读档时加成残留。

接入现有代码：

- `PrototypeData.cs`：增加三属性枚举、职业主属性、本局副属性类型、武器绑定、基础ATK、属性修正、卡牌倍率与实例引用；新增统一定点数值类型承载伤害、生命及格挡。校验副属性必须属于另两项之一。新物品使用稳定配置ID；保留旧枚举数值，不重排旧卡牌／物品枚举。
- `PrototypeGame.cs / PrototypeTown.cs`：新局确认面板加入副属性二选一，未选定不能创建新局；继续入口恢复原选择，不重复询问。取消出发不生成地图、不改变已有存档。
- `TownProgression.cs`：天赋写入本局修正来源；机制天赋继续独立生效。开始新局才捕获当前天赋。
- `RunSystems.cs`：升级按主属性及所选副属性应用成长；背包校验武器绑定并完成装备交换和三属性增益使用；战斗读取实际ATK、卡牌倍率及副属性最终乘区；战斗结束统一处理增益到期。
- `MapGenerator.cs`：将武器奖励交给按本局角色模板过滤的生成入口，测试空池和保底不能生成其他角色武器。
- `PrototypeInterface.cs / PrototypeTown.cs`：接入角色面板、换装提示和动态卡牌数值，避免保留第二份公式。
- `PrototypeStore.cs`：升级存档版本、验证物品归属、处理旧档迁移。现有60～75生命及0～3攻击／防御加成的硬编码校验必须替换，使用配置与来源验证。

进入战斗时构建本场属性上下文；装备、等级和天赋在战斗期间不变，战意等临时效果即时叠加。当前生命沿用并写回本局；格挡、能量、手牌和回合增益仍只属于当前战斗。

## 9. 存档兼容与新局重置

新格式保存角色模板与成长规则快照、主属性与本局所选副属性、三项属性来源、武器模板绑定及基础ATK／属性修正快照、卡牌倍率及副属性每点10%规则快照、天赋快照、当前生命、装备实例及槽位、本局永久增益、剩余战斗次数和数值精度版本。有效属性、实际ATK与副属性伤害倍率是可重建结果，不能同时作为第二份权威数据保存。读取时校验主、副属性不同，且均属于力量／敏捷／智慧。

旧存档不能按当前城镇天赋或新等级公式重新生成属性。建议采用旧版规则快照：

- 模板映射为骑士旧版；保留旧生命上限、攻击加成、格挡加成和开场／战后机制；继续使用旧版固定卡牌伤害，不将旧攻击加成当成新版力量，也不套新版武器倍率公式。
- 保留当前等级、生命、卡组和全部物品，不给历史等级补发属性成长；该进行中旧局继续使用旧版“升级只选牌”，直到正式结束。
- 旧格式没有副属性选择，按旧规则继续，不自动补选或赠送最终伤害加成；新局才进入三属性与副属性流程。以后支持导入其他尚无副属性字段的中间版本时，也必须显式迁移，不能依赖枚举默认值把力量误作副属性。
- 装备槽与增益列表初始化为空，仍有模板基础剑盾能力；该旧局原有已生成地图不补刷装备。
- 原文件备份，成功迁移后再写新格式；不会因为继续旧局而读取并叠加最新天赋。

新局使用新版模板，从1级重新生成并重新选择副属性；所有局内成长、临时增益和已穿装备清空，局外仓库与公会成长保留。读取新格式进行中存档时使用其规则快照并保留原副属性选择，避免更新模板后改变同一局的数值。

## 10. 实施顺序与验收

建议按以下顺序实施，每步可独立验证：

1. 三属性、主／副属性选择、武器绑定、属性修正与统一结算。验证25ATK的150%重击基础伤害37.5，智慧10作为副属性后显示并造成75原始伤害。
2. 主／副属性升级成长、角色面板和动态预览，验证智慧选择生效、跨战斗生命与升级不回血。
3. 装备实例、类型许可、交换、掉落与带出仓库闭环。
4. 三属性精华、强攻药剂、持续时间、存档迁移与完整五图试玩。

验收至少覆盖：

- 两个独立角色实例不互相影响，模板资源不被运行时改写。
- 战士主属性为力量，新局只允许敏捷／智慧二选一；不允许选择主属性或未选择直接出发；取消不创建新局，继续存档不重选。
- 智慧与敏捷均可查看、成长和通过装备／物品提高；选择智慧不会改变模板的敏捷初始值或武器的原有属性修正。
- 有效副属性0／5／10分别提供1／1.5／2倍伤害；未选第三属性只按武器修正参与ATK，不能也增加一次最终倍率。
- 同等级同配置产生相同属性；跳过选牌仍获得成长；连续升级正确；失败不升级。
- 本局所有生成的武器模板均绑定本局角色；同类型但属于另一角色的武器也不进入掉落池。错误绑定的测试物品不可穿戴；空池与保底不跨模板。
- 非武器装备按类型许可校验；满包换装成功、满包卸装失败；战斗期间拒绝换装或喝药。
- 装备、天赋、永久精华和临时药剂各计一次；卸装与增益到期完全移除对应来源。
- 相同力量在不同修正模板下产生不同ATK；换装及时重算；150%修正仅贡献属性×1.5，不额外乘基础ATK。
- 升级、反复穿脱生命装备均不产生免费治疗。
- 连击逐段乘一次副属性倍率后减防与抵挡、第一段击杀停止；盾击不读取力量或武器ATK，但吃副属性最终倍率；战意按配置顺序生效。
- 两场药剂恰好覆盖两场实际战斗，切图、存档和取消结算不额外扣次数。
- 智慧副属性10、ATK25时，重击正文显示75及150%ATK／最终伤害＋100%；对应无防御／格挡目标损失75，有防御1／格挡5目标损失69，卡面目标行直接显示69。卡面伤害、目标预览与结算各自数值准确。
- 有效副属性为0时上述重击为37.5；为5时为56.25；战意＋2、智慧10时为(37.5＋2)×2＝79，而不是77。
- 三项属性、武器、增益与战意变化后卡面立即刷新；副属性临时加成到期同时更新ATK和最终倍率；多段预览顺序消耗格挡；小数不提前截断，边界值按统一规则量化。
- 副属性倍率不提高格挡、治疗或敌人伤害；同一副属性同时有武器修正时，其ATK贡献和最终乘区各算一次。
- 已穿装备参与带出且不重复；仓库容量正确；提交中断不复制实例。
- 新旧存档恢复数值一致；旧局不追补等级成长或重套城镇天赋；新局重置局内来源。

所有平衡数值需在五图流程中调试，尤其关注高属性修正武器、高倍率／多段牌与副属性最终乘区的组合，以及永久物理防御对低伤害敌人的压制。副属性每点10%按用户要求线性相加，再作为一个乘区应用，不擅自改成每点连乘或设置上限。敏捷在当前建议中还增加格挡，智慧路线的装备修正与成长需提供对应价值。原敌人生命和旧卡牌点数不能直接证明新版平衡；先验证用户给定演算，再根据每场失血、用牌回合数和主／副属性成长收益，配置基础ATK、修正、卡牌倍率与敌人数值。
